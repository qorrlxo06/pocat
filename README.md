# 지원핏

## 프로젝트 소개

지원핏은 **서울 거주 청년**의 Persona를 바탕으로 실제 중앙부처 복지서비스를 탐색하는 웹서비스 MVP입니다. 현재는 사용자의 관심 조건과 공공데이터의 구조화된 정보를 비교해 관련 사업을 찾고, 상세 자격조건과 신청 정보를 확인할 수 있습니다.

최종적으로는 **관련도 추천 → 실제 상세조건 확인 → Fit 분석 → 신청 준비** 흐름을 지원하는 서비스를 목표로 합니다. 현재 제공하는 관련도는 최종 신청 자격이나 선정 가능성을 의미하지 않습니다.

## 해결하려는 문제

지원사업 정보는 여러 기관과 사이트에 흩어져 있고, 제목만 보고 유용해 보이는 사업도 실제 대상 조건과 맞지 않을 수 있습니다. 사용자는 긴 공고문에서 자격조건과 신청방법을 직접 찾아야 하며, 신청 직전에 추가 조건이나 준비사항을 발견하기도 합니다.

지원핏은 이 과정을 다음 네 단계로 줄이는 것을 지향합니다.

1. **찾기**: Persona와 관련 있는 실제 지원사업 탐색
2. **이해**: 관련도와 추천 이유 확인
3. **확인**: 상세 대상, 선정기준, 지원내용 확인
4. **준비**: 향후 확인할 조건과 신청 행동을 체크리스트로 연결

## MVP 대상

현재 서비스 대상은 **서울에 거주하는 청년**입니다. 중앙부처 복지서비스 API가 서울 정책만 반환하는 것은 아니며, MVP의 사용자 대상 지역을 서울로 한정한 것입니다.

프론트엔드에서 `region`은 사용자가 별도로 고르지 않고 Persona 내부에 `"서울"`로 저장됩니다.

## 현재 Persona

사용자가 입력하거나 자동 저장하는 정보는 다음과 같습니다.

- `age`: 나이
- `region`: `"서울"`로 자동 저장
- `status`: 현재 상태
- `interests`: 관심분야 1~5개 복수 선택
- `householdTypes`: 가구 특성 복수 선택(선택사항)
- `onlineOnly`: 온라인 신청 가능 사업만 볼지 여부

현재 상태 선택지는 대학생, 대학원생, 취업준비생, 직장인, 자영업자, 프리랜서, 무직·휴직, 기타 등을 포함합니다. 관심분야는 중앙부처 복지서비스 API의 관심주제 구조에 맞춰 구성했으며, 기존의 `생활`과 `창업`은 현재 선택지에서 제외되어 있습니다.

## 현재 데이터 소스

### 중앙부처 복지서비스 OpenAPI

현재 검색과 상세조회는 공공데이터포털의 **중앙부처 복지서비스 OpenAPI**를 사용합니다. Express 백엔드가 XML 응답을 받아 `fast-xml-parser`로 해석한 뒤, 지원핏에서 사용하기 쉬운 JSON으로 정규화합니다.

목록에서 사용하는 주요 필드는 다음과 같습니다.

- `id`, `title`, `description`
- `categories`, `lifeStages`, `targetGroups`
- `ministry`, `department`
- `supportCycle`, `supportType`
- `onlineApplicationAvailable`
- `contact`, `detailUrl`

상세조회에서 사용하는 주요 필드는 다음과 같습니다.

- `target`, `selectionCriteria`, `support`
- `applicationMethods`, `contacts`, `relatedSites`
- `forms`, `legalBasis`

API에 없는 값은 임의로 만들어 반환하지 않습니다. 값이 없으면 빈 배열, `null`, 정보 없음 등 안전한 형태로 처리합니다.

### SH 공개 주거공고

`GET /api/sh-housing`은 SH(서울주택도시개발공사) 공식 공개 게시판의 목록 HTML을 직접 읽어 최대 10건의 주거공고를 정규화하는 백엔드 기능입니다. 사용자가 관심분야 중 '주거'를 선택하면 중앙부처 복지서비스와 함께 독립적으로 병렬 조회되어, 프론트엔드에서 '서울 주거공고' 섹션으로 구분되어 표시됩니다.

## 현재 검색 방식

```text
Frontend
  ↓ GET /api/welfare & (주거 선택 시) GET /api/sh-housing (Promise.allSettled 병렬 요청)
Express Backend
  ↓ 중앙부처 OpenAPI(XML) / SH 게시판(HTML) 정규화
지원핏용 JSON 응답
  ↓
Frontend 결과 표시 (출처별 분리 렌더링)
```

목록 검색에 실제로 사용하는 Persona는 다음 세 가지입니다.

- `age`
- `interests`
- `onlineOnly`

`region`, `status`, `householdTypes`는 Persona로 보관하지만 현재 목록 API의 강제 필터로 사용하지 않습니다. 복수 관심분야는 **OR 조건**으로 처리합니다. 관심분야 수만큼 외부 API를 반복 호출하지 않고, 후보 목록을 한 번 조회한 뒤 백엔드에서 `categories`를 기준으로 필터링합니다.

## 현재 관련도 추천 로직

현재 추천은 과거의 가상 데이터 기반 자격판정이 아니라, Persona와 실제 API 데이터 사이의 **관련도**를 계산합니다.

### 관심분야 점수

- 첫 번째 명시적 일치: `+60`
- 추가 일치: 항목마다 `+10`
- 관심분야 점수 최대: `80`

### 가구 특성 점수

- 선택한 `householdTypes`가 `program.targetGroups`와 명시적으로 일치: `+20`

### 관련도 등급

- 80점 이상: 관심 조건과 매우 관련 높음
- 70점 이상: 관심 조건과 관련 높음
- 그 외: 관심 조건과 관련 있음

최대 점수는 100점입니다. `relatedScore`는 **신청 가능성, 자격 충족 확률, 선정 확률이 아닙니다.** 사용자의 관심 조건과 사업의 구조화된 정보가 얼마나 관련 있는지를 보여주는 값입니다. `targetGroups`가 비어 있거나 일치하지 않아도 감점하거나 신청 불가로 판정하지 않습니다.

## 상세조회

결과 카드에서 **자세히 보기**를 누르면 선택한 사업에 대해서만 다음 API를 호출합니다.

```text
GET /api/welfare/:servId
```

상세 모달에서는 실제 응답에 존재하는 지원 대상, 선정 기준, 지원 내용, 신청 방법, 문의처, 관련 사이트, 관련 서식·자료, 관련 법령을 표시합니다. 목록 카드 생성 시 모든 상세 API를 미리 호출하지 않습니다.

## 추천 및 자격판정 설계 원칙

지원핏은 현재 최종 신청 자격을 자동으로 확정하지 않습니다.

- 실제 데이터에 존재하는 정보만 사용합니다.
- 근거 없는 조건이나 필요서류를 생성하지 않습니다.
- 관련도 점수와 자격 가능성을 혼동하지 않습니다.
- 정보가 부족하면 `추가 확인 필요`로 표시합니다.
- Persona에 없는 조건을 임의로 추론하지 않습니다.
- 최종 자격과 신청 가능 여부는 공식 공고에서 확인해야 합니다.

향후 OpenAI 기능도 자격조건을 결정하는 역할이 아니라, 규칙 및 Fit 분석 결과를 사용자가 이해하기 쉽게 **설명하는 역할**로 제한할 예정입니다.

## 시스템 구조

현재 구조는 다음과 같습니다.

```text
Browser (index.html / app.js)
  ↓
Node.js + Express Backend (server.js)
  ├─ 중앙부처 복지서비스 OpenAPI (XML 파싱 및 JSON 정규화, 로컬 캐시 레이어)
  └─ SH 서울주택도시공사 공개 게시판 (cheerio 기반 HTML 파싱)
```

중앙부처 복지서비스와 SH 서울 주거공고는 프론트엔드에서 독립된 출처로 분리되어 렌더링되며, 복지서비스 상세 모달을 통해 근거 기반 Fit 분석 및 신청 전 확인 체크리스트를 제공합니다.

## 실행 방법

Node.js가 설치되어 있어야 하며, 프론트엔드는 Express 서버를 통해 실행합니다.

1. 터미널에서 `server` 폴더로 이동합니다.

```bash
cd server
```

2. 처음 실행하거나 의존성이 변경된 경우 패키지를 설치합니다.

```bash
npm install
```

3. `server/.env.example`을 참고해 `server/.env`를 만들고 환경변수를 설정합니다.

```dotenv
PUBLIC_DATA_API_KEY=YOUR_API_KEY_HERE
PORT=3001
```

실제 API 키는 코드, README, Git 저장소에 기록하지 않습니다.

4. 서버를 실행합니다.

```bash
npm start
```

개발 중 파일 변경을 감지하려면 다음 명령을 사용할 수 있습니다.

```bash
npm run dev
```

5. 브라우저에서 다음 주소를 엽니다.

```text
http://localhost:3001
```

`index.html` 더블클릭이나 VS Code Live Server의 `Go Live`로 열면 상대경로 `/api/welfare`가 올바른 Express 서버를 바라보지 않아 검색이 작동하지 않을 수 있습니다. 현재는 반드시 `http://localhost:3001`을 사용해야 합니다.

## 확정 로드맵

### 1. 근거 기반 자격조건 Fit 분석기

Persona와 실제 상세 데이터의 `target`, `selectionCriteria`를 비교합니다.

- `✓ 확인된 일치`
- `✕ 확인된 불일치`
- `? 추가 확인 필요`

Persona에 필요한 정보가 없으면 추론하지 않고 **더 정확한 분석을 위해 추가 정보가 필요함**을 안내합니다. 소득, 무주택 여부, 재학 여부 등은 실제 선정기준에서 필요할 때만 점진적으로 질문합니다.

### 2. 신청 준비 코파일럿

Fit 분석의 `? 추가 확인 필요` 항목을 행동 가능한 체크리스트로 연결합니다. 실제 상세 API의 신청 방법, 문의처, 서식·자료, 관련 사이트를 활용합니다.

MVP에서는 자동 신청, 문서 자동 제출, 근거 없는 필요서류 생성을 하지 않습니다.

### 3. SH 서울 주거공고 확장

현재 독립적으로 구현된 SH 목록 조회를 바탕으로 상세정보와 데이터 품질을 검증해 서울 청년의 주거 분야를 강화합니다.

### 4. 중앙부처 + SH 통합 추천

사용자가 주거 분야를 선택하면 중앙부처와 SH의 결과를 한 서비스에서 확인할 수 있도록 확장합니다. 각 사업의 데이터 출처는 명확히 구분합니다.

### 5. OpenAI 설명 기능

- 판단: 규칙 및 Fit 분석 엔진
- 설명: OpenAI

OpenAI가 지원 자격이나 조건을 임의로 생성하지 않도록 하고, 근거가 있는 분석 결과를 이해하기 쉽게 설명하는 데 사용합니다.

### 6. 전체 UX 및 E2E 개선

- loading 및 empty state
- API failure와 정보 부족 처리
- 전체 사용자 흐름 검증
- 사용하지 않는 초기 데이터 정리
- 최종 문서화

## 보안 및 데이터 안내

- 실제 공공데이터 API 키는 `server/.env`에서만 관리합니다.
- `.env`와 `node_modules`는 Git에 커밋하지 않습니다.
- API 키, `serviceKey`, 키가 포함된 전체 외부 요청 URL을 로그나 사용자 응답에 노출하지 않습니다.
- 지원핏의 결과는 관련 정보 탐색을 돕기 위한 것이며, 최종 자격과 최신 일정은 반드시 공식 공고에서 확인해야 합니다.
